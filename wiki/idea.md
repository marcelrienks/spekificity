Part of this setup will then also install all of spekificity dependancies (specify, obsidian, lat.md, and caveman). Than using spek init cli function, within a given directory (this again matches specify), along with any other input params that may be needed all the skills (py scripts set up to function like skills, again exactly the same as speckit), functions, and logic needed by this project are installed in .spek directory within given location. This will also in effect run specify init under the covers to ensure that it is also fully initialised in the directory. That is how the setup is intended to work.

From a functionality standpoint spekificity only wraps, and consolidates existing best tools for the job (note it does not try to hide the tools, these tools can and should be interacted with directly if and when needed, so they must be made available to the user). Current best practice for solving the major shortcumings of ai agents, is persistent memory (obsidian), token consumption (lat.md for source and wiki), spec driven development (speckit), as well as reducing verbosity (Caveman). All of these must be setup as part of spekificity setup (spekificity wraps the setup of all dependants, and whatever custom logic it may have itself), as well as having all these be linked together and functional by using spek init (similar to specify init). Ultimately all that spekificity does it consolidate all theses tools, and the workflow between all of them (including replicating the speckit workflow) to ensure that speckit benefits from obsidian, and lat.md in the process of executing it's spec driven development.
